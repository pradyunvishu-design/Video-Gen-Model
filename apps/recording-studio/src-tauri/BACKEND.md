# Local studio backend

All recording and editing commands are scoped to backend-owned project IDs and files. No IPC accepts executable paths or command strings. Executable overrides come only from the process environment / local `.env`. No network clients, hosted transcription, publishing, or analytics are implemented.

## Capture implementations

Windows: real FFmpeg `gdigrab` of desktop-composited pixels, strictly bounded to the selected monitor, region, or selected window's client rectangle. This deliberately avoids HWND BitBlt, which produced all-black GPU-backed Chrome recordings in native visual testing. There is no unbounded full-desktop fallback for window mode. Enumeration and coordinate checks use per-monitor-v2 DPI awareness for physical pixel bounds. Window start attempts to bring the explicitly selected window to foreground; preflight and 20 Hz checks verify actual visibility, fixed bounds, and nine occlusion probes. Foreground ownership alone is not required: another non-overlapping window may hold focus safely. If the window moves, resizes, minimizes, disappears, or fails the occlusion probes, the recorder receives graceful Stop and preserves its partial file plus warning. Click Stop in the UI to finalize that preserved recording. Only the exact protected HUD handle is exempt from occlusion checks. Small/transient overlays can fall between probes; keep notifications/overlays off and the target unobstructed. This is visible-area recording, not background/off-screen window capture. DRM/protected surfaces may still be blank.

Region coordinates are validated against the selected display. Optional microphones are enumerated by FFmpeg DirectShow and accepted only from that list. Native Win32 enumeration excludes the studio itself. Cursor position and left-button state are sampled locally at 20 Hz; very short clicks can be missed. Pointer data stays next to the source in `cursor.json`; the exact selected pixel rectangle is retained in `capture-area.json`.

macOS: the native Swift companion uses ScreenCaptureKit `SCStream` plus macOS 15 `SCRecordingOutput`, including an optional selected microphone. It is compiled by Xcode 16+ during the macOS Cargo build and embedded in the Rust executable, then installed under app-local data. Screen recordings explicitly exclude the studio/HUD windows. Cursor metadata is sampled locally. Region pixel coordinates are converted to ScreenCaptureKit's logical screen coordinates. Screen and microphone permission failures are recoverable. The Windows development machine cannot compile, execute, sign, or verify this macOS path; a macOS smoke test remains mandatory before claiming tested support. CLI helper usage descriptions are embedded; the app's Info.plist also supplies usage descriptions. The current minimum macOS version is 15, not older versions.

Recording requires an explicit start. Main studio hides during capture; the always-on-top HUD and tray offer Stop. Windows content protection asks the OS to exclude the HUD; support depends on OS/capture behavior. Stop sends a graceful quit to the native recorder, waits up to 15 seconds, and preserves source/logs even on failure. Windows source is fragmented MP4 with a 60-frame GOP, balancing browser playback and recovery of completed fragments; macOS native source is MP4. A crash may leave a source folder that was not indexed; never delete it. No automatic desktop capture or recovery capture occurs on launch.

## Editing and exports

SQLite stores projects and editable plans. Source files are never written by editing/export commands. Crop, trim, padding, zoom scales/times, colors, and callout lengths are validated. Click edges suggest restrained 1.35× zooms at least 2 seconds apart, capped at 24; users can revise/remove them. Export uses 30 fps, cosine zoom easing, source-aligned click highlights, safe text files for callouts, and exactly 1920×1080 output. Callout coordinates are normalized output coordinates; zoom points are normalized source coordinates. All event times use the original untrimmed source timeline.

H.264/AAC MP4 and VP9/Opus WebM exports run on worker threads. Cancellation kills only the export child, retaining partial output and original edits. Every completed export receives a poster, transcript text, extractive summary, and frozen edit plan. The summary is an excerpt of up to three transcript sentences, not an LLM-generated semantic summary. Optional whisper.cpp runs only when local executable/model files are configured, otherwise manual transcripts work.

`cargo test --lib` runs validation/storage/configuration tests. The ignored `synthetic_export_end_to_end` test generates a labeled synthetic audio/video fixture, exercises zoom/callout exports in both formats, checks size/duration/audio, verifies cancellation, and compares source bytes. `--self-test` creates a synthetic fixture and export without recording a desktop. On Windows, `--capture-test-window "Recording Studio Synthetic Fixture …"` requires `STUDIO_TEST_CAPTURE=1`, matches that exact window title, records only that explicit synthetic window for two seconds with microphone off, and exports it. It refuses other titles and never falls back to a screen source.
